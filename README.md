# PermitFlow

מערכת דמו מקומית להגשה, לבדיקה ולהנפקה של היתרי כניסה. החשבונות, הבקשות וכללי הזכאות בפרויקט פיקטיביים. השתמשו רק בקבצים ובנתונים סינתטיים.

## הרצה

מתיקיית המאגר, עם Docker ו־Docker Compose:

```sh
docker compose up --build -d
docker compose ps
```

- הממשק זמין ב־[localhost:3000](http://localhost:3000). בורר התפקידים מחליף בין שלושת חשבונות הדמו.
- אפשר לנסות את הפעולות ב־[Swagger UI](http://localhost:8080/swagger-ui/index.html) ולקרוא את [מפרט OpenAPI](http://localhost:8080/v3/api-docs). ב־Authorize התחברו כ־`demo-applicant`, `demo-reviewer` או `demo-admin` עם הסיסמה `permitflow-demo`. בפעולות שמבקשות את הכותרת `X-PermitFlow-Demo` הזינו `1`. בהגשה הזינו UUID בכותרת `Idempotency-Key`.
- NiFi נמצא בפרופיל `import`. הוראות הקמת הזרימה בפעם הראשונה נמצאות ב־[demo/NIFI.md](demo/NIFI.md).
- דימוי MinIO נבנה מקוד המקור של מהדורת הקהילה. הבנייה הראשונה מורידה את התלויות ומקמפלת את השרת. [מהדורת MinIO](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z)
- עצירה מקומית באמצעות `docker compose down` משאירה את הנתונים בכרכים.

## תרחיש לראיון

1. בתור מבקש, הגישו בקשת ביקור דמו לשבעה ימים. שמרו את מזהה הבקשה.
2. בפרטי הבקשה העלו את [קובץ הדמו](demo/demo-document.txt) והורידו אותו בחזרה.
3. החליפו לבודק, מצאו את הבקשה לפי המזהה, פתחו בדיקה ואשרו.
4. החליפו למנהל, פתחו את הבקשה והנפיקו היתר. בפרטי הבקשה יופיעו מזהה ההיתר, תוקפו וההיסטוריה.
5. עברו בין עברית, אנגלית, ערבית ורוסית ובדקו את כיוון הממשק. כדי להדגים דחייה, הגישו בקשת אירוע ל־21 ימים.
6. להצגת הקרנת האירועים ב־MongoDB הריצו `docker compose exec mongo mongosh permitflow --eval "db.application_events.find({}, {_id: 1, eventType: 1, applicationId: 1}).toArray()"`.

## ארכיטקטורה

| רכיב | תפקיד |
| --- | --- |
| `backend/` | יישום Java 21 אחד. Spring Boot 3 היא מסגרת העבודה שעליה בנוי שרת ה־API. המודולים מחולקים לבקשות, אבטחה, אירועים ומסמכים. |
| `frontend/` | רכיבי React ב־`view`, מצב מסך ב־`viewmodel`, לקוח API וולידציה ב־`model`, וקובץ נפרד לכל שפה ב־`i18n`. |
| PostgreSQL | מקור האמת למבקשים, בקשות, החלטות, היתרים, היסטוריית סטטוסים, מטא־דאטה של מסמכים, קבלות ייבוא ו־Outbox. Flyway מנהל את הסכמה. |
| Kafka | מעביר אירועים עסקיים ונושא שורות ייבוא. נושא האירועים מחולק לפי מזהה בקשה באמצעות מפתח הודעה. בפריסה המקומית יש מחיצה אחת לברוקר יחיד. |
| MongoDB | הקרנת ביקורת לקריאה של אירועים עסקיים, עם מסמכי JSON בעלי מבנה גמיש. הצרכן מבצע רק insert ו־MongoDB אוכף ייחוד על מזהה האירוע. |
| Redis | מטמון עם TTL של חמש דקות ל־`GET /api/applications/rules/{purpose}`. ספירת הגשות חדשות לחשבון היא אטומית ומוגבלת לעשר בחלון של דקה. |
| MinIO | מאחסן את תוכן קובצי הטקסט הסינתטיים. מזהה האובייקט נגזר ממזהי הבקשה והמסמך. |

## מצבים והרשאות

```text
SUBMITTED → IN_REVIEW → APPROVED → ISSUED → EXPIRED
                     ↘ REJECTED
```

מבקש מגיש ורואה את הבקשות שלו. בודק פותח בדיקה ומחליט. מנהל יכול גם להנפיק. ביקור דמו זכאי עד 30 ימים ואירוע דמו עד 14 ימים. בקשה מסוג אחר אינה זכאית. הנפקה יוצרת היתר אחד לבקשה שאושרה, עם תוקף לפי משך הבקשה. שליחה חוזרת של פעולת ההנפקה בזמן שההיתר בתוקף מחזירה את ההיתר הקיים. משימה מתוזמנת מעדכנת מצבים שפג תוקפם. טבלת המעברים בקוד נמצאת ב־`ApplicationStatus`.

## עקביות ותקלות

- מפתח האידמפוטנטיות ייחודי לחשבון ולמקור ההגשה. בקשה חוזרת עם אותו תוכן מקבלת את אותה בקשה. שימוש חוזר במפתח עם תוכן אחר מחזיר 409.
- שינוי עסקי ואירוע Outbox נכתבים באותה טרנזקציה. המפרסם מסמן רשומה אחרי אישור Kafka. תקלה בין האישור לסימון עשויה להביא לפרסום חוזר. צרכן הביקורת מדלג על מזהה אירוע שכבר נשמר.
- בייבוא, PostgreSQL שומר בקשה וקבלת ייבוא באותה טרנזקציה. UUID סינתטי מזהה שורה גם בקובץ ששמו או תוכנו השתנו. שימוש חוזר במזהה עם תוכן אחר נשלח לנושא השגיאות.
- בהעלאה, המטא־דאטה מתחילה במצב ממתין. לאחר כתיבה ל־MinIO הרשומה הופכת לזמינה. ניסיון חוזר עם אותו תוכן משתמש באותו אובייקט ומאפשר להשלים העלאה שנקטעה.
- במקרה של תקלה ב־Redis, מידע העזר נשאר זמין מתוך כללי השרת. הגשה חדשה נעצרת עד שהגבלת הקצב חוזרת לפעול, ושידור חוזר של הגשה שנשמרה עדיין מחזיר את הבקשה הקיימת.

## בדיקות

```sh
mvn -f backend/pom.xml verify
cd frontend
npm ci
npm run build
```

אחרי שינוי ב־API, כשהשרת המקומי פעיל, הריצו `npm run generate:api` מתיקיית `frontend` כדי לעדכן את טיפוסי הלקוח.

אפשר להריץ בדיקת זרימה מול מופע Compose פעיל ממערכת שיש בה Node.js 22 ומעלה:

```sh
node demo/smoke.mjs
```
